# Basair Quran — P201 / QA-050 — إصلاح بقايا التمرير خلف المصحف الثابت

تاريخ الفحص: 17 نوفمبر 2026
الأساس: تطبيق V695 / P200-Seq99 / tilawa v217.

## بلاغ المالك
عند تشغيل متابعة الطبعة الملوّنة تبقى الصورة الثابتة ظاهرة، ولكن تظهر خلفها حركة التمرير القديم بلا الرأس الأخضر.

## العلة المؤكدة من المصدر
- P200 يخفي `#pageReading` بـ `visibility:hidden`.
- CSS الخاص بـ R33 يفرض على بعض الأحفاد (`.r33PrintShell`, `.r33PrintImage`, `.ayahHitLayer`) قيمة `visibility:visible!important`.
- CSS `visibility` قابل لإعادة إظهار الأحفاد حتى مع اختفاء العنصر الأب؛ لذلك لا يكفي إخفاء الأب وحده.
- أصل الواجهة: `#b345NormalStack` داخل `#mushafPage` داخل `#pageReading`. أدوات `#sequenceMiniControl` و `#mushafDock` خارج `#pageReading`.

## الإصلاح
إضافة ملف CSS واحد `p201-legacy-occlusion.css` إلى وحدة التلاوة، يُطبّق `opacity:0!important` على `#pageReading` عندما تنجح بوابة P200 ويصبح عارض P199 الثابت جاهزًا. شفافية العنصر الأب مركّبة مع أحفاده، حتى لو أصر أحدهم على `visibility:visible`. يُمنع التقاط لمس الصفحة القديمة بـ `pointer-events:none` على الحاوية. لا تعديل أو إضافة لصورة المصحف أو الإطار أو الرأس أو محرك الصوت.

## اختبار Chromium المنفّذ بالمصدر الحقيقي P199/P200
1. بدء صفحة المصحف بدون متابعة: `opacity:1` — PASS.
2. بعد المتابعة: P199 وP200 جاهزان — PASS.
3. إخفاء الأب `opacity:0` مع بقاء قواعد `visibility:visible!important` في صور B345 — PASS.
4. احتفاظ حاوية التمرير بقياسها الكامل مع استمرار تغيّر `scrollTop` — PASS.
5. ظهور أزرار المتابعة مستقلة عن حاوية القراءة — PASS.
6. الانتقال من الصفحة 4 إلى 5 مع نسخة واحدة من صفحة المصحف الثابت — PASS.
7. التوقف يعيد `opacity:1` ويزيل حالة P200 — PASS.
8. الخطوط الرقمية مستثناة — PASS.
9. لم تظهر أخطاء JavaScript — PASS.

الاختبار على Chromium محاكاة مركزة لواجهة DOM وليس بديلًا عن Android WebView. اختبار الهاتف لاحق للنشر شرط اعتماد المالك.
