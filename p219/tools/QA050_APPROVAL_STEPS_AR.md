# الخطوة الوحيدة المطلوبة من بيئة توقيع QA-050 الأصلية

هذه التعليمات تخص موافقة قفل بصائر القرآن QA-050 **المستقلة**. موافقة المستخدم في ChatGPT تفوض متابعة العمل، لكنها لا تصنع توقيع Ed25519 الذي يشترطه الحارس.

1. على جهاز/بيئة التوقيع الموثوقة التي تحتفظ بالمفتاح الأصلي المطابق لـ`ci/tilawa-owner-approval-public.pem`، افتح النسخة المحلية للمستودع `nmg200101-collab/basair-tafsir-updates`.
2. تأكد من استخدام فرع `security/qa050-protect-ownerqa-tilawa-20261123` بعد جلب أحدث `origin/main`. **إذا تغيّر الأساس فلن تقبل الأداة التوقيع القديم**.
3. نفّذ الأمر التالي مع **مسار المفتاح المحلي خارج المستودع فقط**:

```bash
python3 p219/tools/qa050_sign_request.py \
  --key /trusted/external/path/original-qa050-private.pem \
  --request ci/tilawa-approvals/P219_QA050_GUARD_SCOPE_REQUEST_20261123.json \
  --write
```

4. الأداة تتحقق من نطاق الملفات المحمية ومن التوقيع مقابل المفتاح العام الأصلي، وتكتب التوقيع العام Base64 داخل JSON فقط. نفّذ `git add ci/tilawa-approvals/P219_QA050_GUARD_SCOPE_REQUEST_20261123.json` ثم `git commit` و`git push` لهذا الملف فقط، ثم تحقق من GitHub Actions في PR #174.
5. **بعد الدمج الصحيح للطلب #174 فقط:** يحتاج PR #173 موافقة QA-050 منفصلة مرتبطة بأساس `main` الجديد وفرق إضافة `p219-native-single-shadow-owner.js`. لا تصلح موافقة #174 لإطلاق #173.

قواعد الأمان: لا تشارك المفتاح الخاص أو كلمة مروره، ولا ترفع ملف المفتاح إلى GitHub أو ChatGPT، ولا تُعدّل المفتاح العام أو قواعد الحراسة للتحايل على التحقق. لا تُنشر P219 / Seq131 قبل الموافقة المستقلة على PR #173 وإتمام اختبار التلاوة على Android V695. حزمة الرجوع الموقّعة Seq132 محفوظة.

إذا ظهر الخطأ `QA050 NOT APPROVED` فتوقف وتحقق من سبب الرفض. لا تعيد استخدام مفتاح P119 أو توقيع OTA بوصفه QA-050.
